      Communication sounds

      Communication sounds are off by default and require Audio Cues to be enabled.

      These cues are independent from Self-Voice. Turn channel speech off and keep its sound on when you want an instant notification and review the message later.

      Audio Cues are off by default. Enable them, then test the built-in earcons before creating sound triggers. Vitals cues fire only on real downward threshold crossings: health 75/50/25/10, mana 20/5, and movement 50/5.

      Audio Cues use NukeFire's internal Web Audio engine; they do not launch a media player or execute a system command. Background suppression uses the same whole-application focus state as Self-Voice, so NukeFire pop-out panes still count as foreground. Cues play immediately and are never queued for catch-up after mute or background time.

      Sound triggers

      Match completed plain game lines and play one of the built-in Audio Cues. Patterns use familiar Action-style wildcards: %1 through %99 or %*. Matching text always remains in the terminal and Reader Review. Suppression affects only NukeFire Self-Voice.

      Native screen reader mode is the standard VoiceOver, NVDA, JAWS, or Orca path. Reader workspace is presentation-only: ordinary panels and their pop-out windows are hidden while their data, automation, Communications, mapper, and session processing continue; turning it off restores the normal workspace. NukeFire self-voice is optional and uses the system speech synthesizer for live game lines and reader announcements. Speed ranges from 0.1× to 10× for experienced reader users; pitch, volume, and any system voices exposed by the platform are independently selectable. Mute keeps Self-Voice enabled but silent until unmuted. Foreground-only speech is on by default: when NukeFire loses application focus, current and queued Self-Voice are discarded while all game, review, Communications, mapper, and automation processing continues; returning to NukeFire resumes only new live speech. Backlog condensation preserves normal bursts, but if fresh output keeps arriving while speech is still behind it keeps the newest lines and announces how many stale lines were condensed; every real line remains available in terminal history and Reader Review. Priority Tell and System lines can barge in over stale live speech; interrupted text remains available in Reader Review and Communications. Follow self-voice interrupts stale speech when the active character starts a recognized movement or arrives in a different Room.Info room. Enabling one live-reading mode disables the other so they do not speak the same game output at once.

      Command-L focuses the command line. Command-Shift-O reviews output. Command-Shift-L reads the current docked prompt when present, otherwise the last output line. Current, Previous, Next, and Latest Reader Line use an independent per-session review cursor, so new game output does not move the line being reviewed. Command-Shift-V reads vitals.
