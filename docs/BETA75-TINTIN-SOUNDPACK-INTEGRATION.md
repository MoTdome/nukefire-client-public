# NukeFire Client Beta.75 — TinTin → Soundpack Integration Pass 2

This pass adds one deliberately small bridge between TinTin automation and the existing managed NukeFire soundpack system.

## Player command

```text
#SOUND {event}
```

`#SOUND` never takes a filename or filesystem path. It asks NukeFire to play one managed soundpack event through the same Audio Cues gates already used by semantic server/client sounds.

Typical player-created use:

```text
#ACTION {a dungeon staircase} {#SOUND {custom.stairs}}
```

Player-created event names must use the `custom.*` namespace, for example:

```text
custom.stairs
custom.secret-door
custom.low-health
```

Names are bounded to 80 characters and use lowercase letters, numbers, dots, underscores, or hyphens. A soundpack may define at most 32 `custom.*` events.


## Discovering event names

Players do not have to memorize the sound-event vocabulary. `#SOUND` command words and event names are case-insensitive, so `#sound`, `#Sound`, and `#SOUND` are equivalent.

```text
#SOUND {LIST}
#SOUND {LIST} {communication}
#SOUND {LIST} {custom}
#SOUND {SEARCH} {stairs}
#SOUND {SHOW} {custom.stairs}
```

`#SOUND {LIST}` prints the currently playable event groups and counts instead of dumping a large catalog. `LIST {group}` shows the event names in that prefix group. `SEARCH {text}` searches playable event names/source notes, and `SHOW {event}` reports where the event comes from, whether the active pack has an assignment, whether it is enabled, and whether playback is currently ready or blocked.

Reserved/not-emitted semantic names are deliberately omitted from normal LIST/SEARCH discovery so players are not encouraged to bind Actions to events that cannot currently play. If a player already knows one of those names, SHOW can still explain why it is reserved. LIST/SEARCH/SHOW are interactive discovery operations; they do not produce output when invoked from Actions or other automation.

## Where the audio lives

The TinTin Action stores only the event name. The audio itself lives inside the player's editable `.nfsp` soundpack archive under NukeFire's existing managed Soundpacks storage. Assigning a WAV, MP3, OGG, or M4A file copies that file into the archive; the source file does not need to remain in its original location afterward. Exporting the `.nfsp` carries the custom event names and audio assignments together.

This keeps the architecture simple:

```text
TinTin Action
    ↓
#SOUND {custom.stairs}
    ↓
managed event name
    ↓
active .nfsp soundpack
    ↓
assigned audio
    ↓
existing Audio Cue playback gates
```

## Easy setup

Preferences → Audio → Soundpack Editor now includes **Custom Action event**.

1. Enter `custom.stairs`.
2. Choose **Use Custom Event**.
3. If Built-in NukeFire is active, NukeFire automatically creates/uses an editable `personal-sounds` / **Personal Sounds** pack (or honors the new pack ID/name already entered).
4. Choose **Assign Audio File**.
5. Put `#SOUND {custom.stairs}` in an Action, Alias, Function, Event, Delay, or other normal TinTin command body.

No audio path is written into the TinTin script.

## Playback and chatter

`#SOUND` uses the same managed playback policy as the rest of the soundpack system. It can be blocked by event disable state, Audio Cues being off/muted, foreground policy, unavailable audio, zero volume, or cooldown.

A manually typed `#SOUND {custom.stairs}` is the test path and reports the concrete reason when it cannot play. A `#SOUND` generated by an Action/Event/Ticker/Delay/etc. stays quiet if blocked so a missing sound cannot flood combat output. With COMMAND ECHO on, a successful manual test may also report that it played.

Custom events intentionally have no synthesized built-in fallback. If `custom.stairs` has no assigned audio in the active soundpack, it is reported as unassigned rather than playing an unrelated default tone.

## Scope boundary

This pass does not add arbitrary file playback, URLs, shell access, JavaScript/Web Audio options, loops, or per-command volume syntax. Sound choice, volume, cooldown, enable/disable, import/export, and playback policy remain owned by the existing NukeFire soundpack system.
